## Contract with `laya answer` (src/main.rs:66–77, 123–153)

- `Answer { input, output, --model (env LAYA_MODEL), --model-variant (default "typed-decisions"), --only }`
  plus global `--models-root` (env `LAYA_MODELS_ROOT`).
- **AS-BUILT MISMATCH**: the driver passes `--model-dir <DIR>`; the binary defines `--model`
  (no `--model-dir`). Clap rejects it: `error: unexpected argument '--model-dir' found`
  (verified against `./target/debug/laya answer --help` and a live invocation).
  The same stale `--model-dir` text appears in README.md:159/162/166 and
  website/src/components/docs/Cli.tsx (ask/answer examples + flag table).
- This mismatch is documented in the feature's architecture block and kept as an assumption
  per the reverse-ACDD convention (document as-built, do not silently fix the driver).

## Testability notes

- All validation/loop behavior is testable without checkpoint weights: a stand-in `laya`
  shell-script binary (records argv to a log, writes deterministic `{qid: answer}` JSON)
  stands in for the real binary via `--binary`. Binary auto-detection is testable by copying
  the driver into a scratch `<repo>/scripts/` layout with a `<repo>/target/debug/laya`
  stand-in, since candidates resolve relative to `Path(__file__)`.
- The end-to-end happy path against the real binary needs a checkpoint; it is the
  as-built-mismatch scenario and is covered structurally (the driver's argv recording proves
  the flag it passes) — gated like `tests/cli_answer.rs` (LAYA_TEST_MODEL) for anything
  needing real weights.
- No test framework in the repo: tests are plain assert-based Python functions
  (`tests/jev_batch.py`), runnable standalone (`python3 tests/jev_batch.py`) or under pytest.
